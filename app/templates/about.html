About the project

Built to teach, not just summarize.

HAS turns lectures and documents into study notes that actually explain things — the story of how it's built, and why it works the way it does.

The architecture

Document → Outline → Topics → Extract → Teach → Merge

The core insight: plan before you write. An outline pass gives the model global awareness before a single sentence of teaching content is generated.

Extractor registry

Every source type — PDF, DOCX, PPTX, YouTube, webpage — has its own extractor behind a SourceFactory, so the controller never needs to know what kind of file it's holding. Everything lands in a shared KnowledgeCollection.

Thin controllers, one job each

PipelineService orchestrates six single-responsibility services in sequence. Controllers only validate input and delegate — no business logic leaks upward.

Chunking is plumbing, not product

A 3-hour lecture can't fit in one call, so text is split paragraph-aware with token estimation. Chunks are an implementation detail — never the unit of generation.

Two-pass extract → teach

Extraction turns raw text into structured JSON — concepts, mechanisms, examples, formulas, pitfalls. Teaching then rebuilds that JSON into markdown with analogies and why-first structure. Separating the two prevents information loss.

Model routing

Outline and extraction can toggle between Gemini 3.1 Flash Lite and Llama 3.3 70B. Teaching and merging always run on GPT OSS 120B via Groq. Per-model TPM is tracked on a rolling 60-second window, with extraction parallelized across 3 workers and teaching across 2.

A gate before export

The merge pass unifies notation and dedupes explanations. A three-layer defense (prompt constraints → regex fix → bracket-balance gate) keeps Mermaid diagrams valid, and a QualityGate linter checks everything before it ships.

How it got here

Five phases, one growing idea

01

Scripts. Just getting it to work

Separate Python scripts for PDF extraction, YouTube transcript downloads, and web scraping. No architecture yet — just proof that the idea worked.

02

Architecture. Giving it a shape

PipelineService became the central orchestrator. The extractor registry pattern arrived, and chunking, rendering, and export split into independent services.

03

Intelligence. Fixing fragmented notes

Chunk-then-summarize produced disconnected notes. Outline-driven generation with topic roles replaced it, along with the two-pass extract → teach system.

04

Quality. Making it trustworthy

Notation drift, conflicting numbers, and repeated explanations got fixed. Mermaid diagrams, callouts, LaTeX, and wiki-links arrived, alongside per-model TPM tracking and provider switching.

05

Frontend. Making it feel like a product

The bare test form was replaced with a real landing page — drag-drop upload, a URL textarea, a shimmering progress bar, and scroll animations.

Who built this

Hi, I'm Arib.

I'm a computer science student focused on machine learning, and this time I didn't want to build just another project — I wanted to build a product.

It came from a habit I'd never really examined: I'd watch a lecture on YouTube or Coursera, drop the link into NotebookLM for a first pass, then rewrite whatever it gave me into a proper Markdown file — often handing it to Claude for a second pass to get notes I'd actually want to reread.

HAS is that entire habit, automated: one pipeline that takes the source and hands back the notes, without the manual relay in between.
